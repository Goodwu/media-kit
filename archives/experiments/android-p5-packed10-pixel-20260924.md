# P5 packed10 与 R32F 同 PTS 分量读回（2026-09-24）

目标机仍为 Huawei LYA-AL00 `3EP7N18C28016072`。在同一 8340 arm64 Release APK 中，以默认关闭的 `debug.media_kit.p5_raw_pixel_probe=1`，从 P5 raw FBO 在 PTS 10.0–11.0 秒逐帧读回固定纹理坐标 `(1920,1080)`：packed10 路径按 `GL_RGBA/GL_UNSIGNED_INT_2_10_10_10_REV` 读取并拆 R/G/B 的 10-bit 值，R32F/MRT 路径依次选三个 attachment 按 `GL_RED/GL_FLOAT` 读取。两路都启用逐帧 RPU 附着、raw YUV、MediaCodec、gpu-next/OpenGL 与 Texture SDR；分别设置 `p5_raw_packed10=1,p5_raw_mrt=0` 和 `p5_raw_packed10=0,p5_raw_mrt=1`。`p5_raw_early_fence=0`，无延迟释放。读回会同步 GPU，只用于数值诊断，**不得用本包掉帧数判断性能**。

packed10 共记录 42 帧、R32F 共记录 28 帧，精确 PTS 与同一坐标的交集为 24 帧。对每个交集分量计算 `packed10_code - round(r32f_normalized * 1023)`，Y/U/V 各 24 个差值全部为 0；两路所有读回 GL error 均为 `0x0`。例如 PTS 10.000 秒，packed 为 `(416,516,509)`，R32F 为 `(0.406862736,0.503921568,0.498039216)`，按 1023 还原并取整也是 `(416,516,509)`。这支持 packed10 的三个物理纹理通道在这些样本中与原 R32F 路径一一对应，没有观察到打包额外改变 10-bit 代码值。

证据只覆盖**同一 GPU 原始 YUV prepass 的一个中心像素和约 1 秒片段**。两路共享厂商 `GL_EXT_YUV_target` 输入，不能据此证明它等于压缩码流原始 10-bit 样本；也尚未比较图像边缘/裁剪点、全部帧、RPU reshape 后的 RGB、最终显示像素或 HDR 激活。R32F 路径该窗口有帧被 VO 丢弃，只对严格相同 PTS 的 24 帧比较，没有用近邻帧凑数。此前 8335 的无热路径探针全片 A/B/A 性能结果见 `android-p5-packed10-runtime-20260924.md`，不能与本诊断包的时间数字混用。
