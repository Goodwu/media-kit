# CI 修复：主 ci.yml 多 job 失败与 OHOS HAP 依赖解析（2026-10-02）

任务：TASKS.md「CI 修复：主 ci.yml 多 job 失败与 OHOS HAP 依赖解析」。事实收集由 Scout 完成（run 37002149440/37023465277/36940311911/37025467236 等日志逐 job 摘录），Lead 抽查核实，修复分五批实施。

## 结论

CI 失败共六类根因，五类已修复（本地验证全绿），一类（Windows 原生崩溃）确证为 fork 特有回归、单列调查任务。关键背景更正：**此前"最后全绿 run 33555639764（ad22c36a，09-01）"实为 feature 分支 `integration/piliplusx-hdr-public-api` 的 workflow_dispatch**——release 步骤被 `if: main` 跳过，并非 main push 曾通过；09-02~09-29 无 main push run，失败集合自 09-30 首个 main run 起持续。

## 失败类别、根因与修复

### ① lockfile 失配（exit 65）——主 ci 六平台构建 job + Linux + OHOS 同根因

- 根因：`420fba3e`（S11 发布）将 `media_kit_video` 1.3.1→1.3.1+1、`media_kit_android_dataspace_vendor` 1.0.0→1.0.0+1，但两个 lockfile 未再生成：`media_kit_test/pubspec.lock` 锁 1.3.1；`pubspec.ohos.lock` 更陈旧（锁 1.2.5、含 js 0.7.2、web 未转直依赖，09-02 后未更新）。`--enforce-lockfile` 要求 path 依赖锁定版本与 pubspec 一致。OHOS 早于版本 bump 就已因 lock 内容陈旧失败（09-30 run "Would change 3 dependencies"）。
- 修复：本机 Flutter 3.47.2（与 CI 钉定一致）最小差异再生成——OHOS lock 从自身基线再生成（js 移除、web 转直依赖、五个 path 依赖版本同步、matcher 0.12.19→0.12.20 / meta 1.18→1.19 / test_api 0.7.11→0.7.12 / vector_math 2.2.0→2.4.3 为约束必要升级；sdks 不变 dart ≥3.12.0 / flutter ≥3.44.0），主 lock 仅 media_kit_video 版本 1 行。

### ② vnext release 步骤权限（"Resource not accessible by integration"）——6 平台 job + manifest job

- 根因：上游继承的 "vnext" 草稿 release 自动化（softprops/action-gh-release，`if: github.ref == 'refs/heads/main'`）需要 GITHUB_TOKEN 写权限，本 fork 保持只读 → main push 必挂（见上，从未成功过）。WinARM64 "Too many retries" 为同源连带。
- 修复：7 处条件加 `github.repository == 'media-kit/media-kit'` 门禁（Windows/WinARM64/Linux/macOS/iOS/Android 六个 step 级 + "Release manifest and checksums" job 级），各留注释说明 fork 只读、发布走手动链。upload-artifact 步骤（无权限要求）保留，逐 run 产物仍可下载。备选方案（开仓库 write 权限让 fork 也产 vnext 草稿）未采用，如需可复议。

### ③ macOS 构建 Swift 可用性（gpuStartTime/gpuEndTime 仅 macOS 10.15+）

- 根因：我方整改 P1-6（`7caaf8dc`）在 `MetalSurfaceBlitter.swift:176-177` 读取 `commandBuffer.gpuStartTime/gpuEndTime`（macOS 10.15+，iOS 10.0+）；`media_kit_video.podspec` 平台为 `:osx, '10.9'` → pod 按 10.9 编译必挂（app target 12.0 不影响 pod 编译单元；本地此前只构建过 hdr_lab，未暴露）。
- 修复：`#available(macOS 10.15, iOS 10.0, *)` 守卫，低于 10.15 的目标报 `gpuDurationSeconds = nil`（无计时数据，非失败）。ios/macos 两份为指向 `common/darwin` 的符号链接，一次编辑三处生效。

### ④ Build Flutter Web 编译失败（dart2js + dart2wasm 两层）

- 根因：Phase 1 HDR 代码（S5 会话/backend）面向 io 编写，web/wasm 编译面缺口：`VideoControlsBuilder` typedef 仅 io 侧（video_texture.dart）；`AndroidVideoController` 四个 HDR 静态成员仅 android real.dart（web 桩缺失）；`WebPlayer` 缺 `getProperty/setPropertyStrict/command`（dart2js 路径）；wasm 下 `dart.library.html` 为 false 使 Player 经 native 桶解析到 `native/player/stub.dart`，同样缺三方法（dart2wasm 路径，改动前即失败、与 dart2js 同窗口引入）。
- 修复（Worker 实施 + Lead 补 wasm 侧，R2.5 透传语义、全部抛错无假值）：
  - `video_web.dart` 补 typedef（与 video_texture.dart 逐字一致）；
  - `android_video_controller/stub.dart` 补四静态成员（UnimplementedError，文件既有风格；门禁调查确认全部调用点在会话 `_isAndroid` 运行时门禁后，web 运行面不可达）；
  - `HdrCapabilitiesChangedListener` typedef 原样迁至 `platform_video_controller.dart` 共享头（real.dart 留指针注释，逻辑零改动）；
  - `web/player/real.dart`+`stub.dart`、`native/player/stub.dart` 各补三方法，签名与 io `NativePlayer` 逐字一致（含 `waitForInitialization`），UnsupportedError。
- 验证：`flutter build web --release` ✓、`--release --wasm` ✓（dart2js 回退与 dart2wasm 双双编译干净）；media_kit_video analyze 18 基线不变、media_kit 4 基线不变；media_kit_video 测试 204/204。

### ⑤ hdr_lab JVM 测试 exit 127（./gradlew: No such file or directory）

- 根因：gradlew/gradlew.bat/gradle-wrapper.jar 被 `media_kit_hdr_lab/android/.gitignore` 三行显式忽略（继承 media_kit_test 模板约定；media_kit_test 构建可过是因 flutter 工具为自身构建注入 wrapper，直连 `./gradlew` 的 CI 步骤则找不到文件）；且该 job 无 JDK 设置（Gradle 8.14 / AGP 8.13 需 17）。
- 修复：提交 wrapper 三件套 + .gitignore 删三行并加说明注释（CI 直连 ./gradlew，flutter 只为自身构建注入）；job 补 setup-java zulu 17（镜像 Android job 既有写法）。
- 本地实证：`flutter pub get` 会生成 `android/local.properties`（settings.gradle.kts 的 flutter.sdk 前提在 CI 成立，挪走原文件复测）；`./gradlew :media_kit_android_dataspace_vendor:testDebugUnitTest` 本地 BUILD SUCCESSFUL（JDK 17，51 tasks）。vendor 子项目经 flutter-plugin-loader 自动注入（.flutter-plugins-dependencies 实证）。

### ⑥ Windows package tests 原生崩溃——未修复，单列调查

- 事实：access violation（0xC0000005）pc 在 `libmpv-2.dll`（CI 钉定 mpv-dev-x86_64-20230811-git-140ec21）内；`asset-loader-encode-asset-key` 通过后约 5 秒、下一播放类套件（dart_test 第 7 isolate）崩溃，早于用例名输出；Dart 3.13.2 VM crash dump（GetAndValidateCurrentThreadStackBounds 失败为崩溃处理器连带）。
- 归因边界：**上游 `media-kit/media-kit` 同 workflow 于 8b4d3afc（09-29 PR run）`package:media_kit tests (Windows)` success** → fork 特有；窗口 = ad22c36a（09-01 workflow_dispatch 绿）→ eacc799a（09-30 首败），即上游合并 `a886f556`（63 冲突裁定）+ 期间我方提交。本地 macOS 无法复现（media_kit VM 套件本地缺 Mpv.framework，72 项既有环境失败，A/B diff 为空）。
- 处置：登记独立调查任务（TASKS Next），计划 workflow_dispatch 分支二分（`run_package_tests=true`，不动 main），首查 a886f556 对 media_kit player/native 路径的冲突裁定。
- **夹具评估与用户决策（2026-10-03）**：用户确认 **Windows 是长期产品目标**，按"夹具现代化是否助力该目标"裁定 Windows 构建/测试 job 保留不关。评估结论：升级钉定（2023-08-11 件 → libmpv-win32-video-build 最新）有实质推进——mpv ~0.36 代 → 接近 fork 基线 0.41；Dart FFI 契约面持续受测防栈腐烂（web 编译面先例）；fork win32 构建件就位后管道直接复用。已排除 ABI 假说：media_kit core 无 fork 专属符号引用（dovi/p5 面全在 media_kit_video Android bridge），fork 对 C ABI 纯加法，老件可正常加载——崩溃属行为交互。调查计划升级为"诊断优先 + 新老夹具 A/B"，详见 TASKS 任务条目。

另：`package:media_kit tests (Web)` 的 player-set-shuffle 单例失败（37002149440 轮，ff780809 轮通过）疑似偶发，本轮修复推送后复看，持续则并入⑥调查。
