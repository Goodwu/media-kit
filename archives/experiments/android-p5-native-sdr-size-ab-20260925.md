# 官方 4K P5 原生 SDR SurfaceView 与输出尺寸对照（2026-09-25）

为区分 Flutter Texture 消费路径与 GPU P5 本身的性能，测试页新增默认关闭的 `MEDIA_KIT_ANDROID_P5_PLATFORM_SDR_DIAGNOSTIC`。仅在已启用P5 RPU构建且选择PlatformView时，把策略固定为与Texture相同的`gpu-next`/MediaCodec、BT.709/BT.1886 SDR、`target-colorspace-hint=auto`、`tone-mapping=bt.2390`，不设置PQ dataspace或强制RGB10_A2。另在Android视频控制器增加默认0的`MEDIA_KIT_ANDROID_PLATFORM_OUTPUT_MAX_WIDTH`，用于诊断性地限制原生Surface buffer尺寸。两个开关均非正式P5 HDR策略或产品默认。策略测试9项通过，目标Dart分析仅原有`use_super_parameters`提示；11043/11044 Debug APK构建均成功，实际使用相同隔离arm64 JAR SHA-256 `0a460208ac37cab80358796db6699f83773e49092f39f096b5b4398e2e8e12fe`。两轮仍用同一Dolby官方Sol Levante 4K/24fps P5、`0x325` raw packed10、RPU、early fence、retire、code scale，并开默认关闭的VO/EGL稀疏探针。PTS10目标日志与11042 Texture均为`target_sys=12,target_prim=3,target_trc=1`；这证明内部目标字段一致，不是独立颜色准确性证明。

**边界与下一步**：这是首次证明该机公开P5在GPU转换后可用原生SDR视图达到整片VO侧24fps，不证明实际屏幕逐帧present、真人流畅/颜色、HDR亮度或物理声画同步；源没有音轨。Texture与SurfaceView除了消费者拓扑，还涉及RGBA/RGBx buffer格式及合成路径，不能把差额仅归因Flutter raster。11043与11044顺序执行，热状态不严格相同，但较后运行的11044反而明显更快，单纯温度解释不足。两轮都有稀疏探针，需无探针复测、同源截图/实际present、重复热稳；P5 PQ/HDR平台输出仍受该机dataspace权限/能力门禁，不能把原生SDR性能成功替代计划中的HDR门禁。设备已删除媒体、属性清零、恢复官方10369并强停。未提交。
