# DV TestKit 本机离屏 GPU 复验（2026-09-25）

在独立临时 FFmpeg n7.1.3 worktree `/tmp/media-kit-ffmpeg-dvtest-host-20260925` 构建最小 `ffmpeg`/`ffprobe`，启用 libplacebo 7.360.1、Vulkan 和 libplacebo filter；没有改系统 FFmpeg 或产品库。运行时指定 Homebrew Vulkan loader 与 MoltenVK 1.4.2 ICD，Vulkan 选中 Apple M4。构建时最小配置必须包含 `scale` filter（libplacebo filter 链接依赖）及 `pipe` protocol（原始数组 stdout）；这两项缺失造成的初始构建/运行失败不计颜色测试。输入仍为 `~/Downloads/test_files/DV_TestKit_v1.zip`，SHA-256 `77ecd80263f04c09ec221d0288a9fb6f46317a9448877377f6f711446c361489`。

复现时在该 FFmpeg worktree 内执行 `./configure --disable-doc --disable-debug --disable-network --disable-autodetect --disable-everything --enable-ffmpeg --enable-ffprobe --enable-protocol=file --enable-protocol=pipe --enable-demuxer=mov --enable-decoder=hevc --enable-parser=hevc --enable-filter=libplacebo --enable-filter=scale --enable-encoder=rawvideo --enable-muxer=rawvideo --enable-libplacebo --enable-vulkan --enable-pthreads --enable-hwaccel=hevc_vulkan`，再 `make -j8 ffmpeg ffprobe`。测试包根目录执行 `DYLD_LIBRARY_PATH=/opt/homebrew/opt/vulkan-loader/lib VK_ICD_FILENAMES=/opt/homebrew/opt/molten-vk/etc/vulkan/icd.d/MoltenVK_icd.json python3 tools/run_tests.py --mode all --ffmpeg /tmp/media-kit-ffmpeg-dvtest-host-20260925/ffmpeg --ffprobe /tmp/media-kit-ffmpeg-dvtest-host-20260925/ffprobe --output /tmp/media-kit-hdr-dv-testfiles-20260925/dv_gpu_all_moltenvk`。这些路径是本机复验位置，移机需按安装位置替换。

运行 `tools/run_tests.py --mode all` 的 5 个主用例×24帧：L1 FFmpeg 原生 YUV、MP4 DV 配置、RPU 语义子集配帧、PTS 顺序、L2 shader 对 CPU 数学参考全部通过；L3 固定 ETM-v1 的 PQ600、PQ1000 全部通过，SDR100 的 P8.1、P8.4、P8.1 B 帧通过，**P5 与 P5 参数切换的 SDR100 按包内最大误差门槛失败**。完整报告在 `/tmp/media-kit-hdr-dv-testfiles-20260925/dv_gpu_all_moltenvk/report.json`，输出数组在同目录。该结果是本机 FFmpeg/libplacebo/MoltenVK 路径，不是 Android 产品路径，也不是 Dolby 官方标准输出。

P5 SDR100 最大绝对差 `0.014778137`（包内门槛 `1/255≈0.00392157`），P5 参数切换相同；各自超过门槛的分量有 1488/760 个，参考值均为 0。P5 示例帧0坐标 `(x32,y106)` 的 G：GPU L2 PQ=`0.2939453`，CPU L2 PQ=`0.2939769`；GPU SDR100=`0.0147781`，CPU math=`0`。L2 的微小误差落在 SDR 色域裁剪零点附近，经 `pow(1/2.4)` 放大。GPU 输出的 L2/L3 float32 文件值均可无损往返 float16，说明当前观测结果位于 FP16 网格；尚未单独证明具体哪一级纹理引入量化。不能简单抬高最终 SDR 阈值掩盖局部问题。

为隔离 L3，以**本次实测 GPU L2 数组**作为 `display_map()` 的输入，再与本次 GPU L3 数组比较：5 个用例×PQ600/PQ1000/SDR100 共 15 组的最大绝对误差均小于 `0.000502`，P99 均小于 `0.000483`，没有分量超过 `0.001`。P5 上述像素的 L3 CPU 条件计算为 `0.0147126`，GPU 为 `0.0147781`。这是同 ETM-v1 算法下的分层诊断，支持 SDR100 主失败来自传入 L3 的精度/边界差异，而不是已发现的映射公式或目标参数错误；由于 CPU/GLSL 算法有共同来源，不构成独立 Dolby 正确性证明。原始端到端两项 FAIL 必须保留，另设 FP16 输入域及零点附近的绝对亮度/分支规则后再冻结判定。

`tools/fault_tests.py` 在此真实 GPU 环境完整运行：5 项数组错误及 P5/P8.1/P8.4 各关闭 DV 的 3 项 live 渲染错误均被检出。两个 pivot 诊断用例也单独运行：L1/配置/RPU配帧/PTS 通过，L2/L3 按测试包设计只标 `DIAGNOSTIC`，不把 runner 的总体 PASS 当数值准入；其最大误差 P5 为 L2 `0.000478`、PQ600 `0.000878`、PQ1000 `0.000708`、SDR100 `0.001370`，P8.4 为 `0.000490/0.000642/0.000723/0.001127`。报告分别位于 `/tmp/media-kit-hdr-dv-testfiles-20260925/dv_gpu_p5_pivots_moltenvk/report.json` 与相邻的 `dv_gpu_p84_pivots_moltenvk/report.json`。下一步将小样本 GPU 门禁接入可复现命令与分层误差报告，再为现有 4K50 P5 的手机 L3 RGBA16F 建立**相同码流、同帧、同 target/policy**的主机工程参考；未对齐前不能跨素材或跨映射策略比较。
