The probe creates a public API24 `AImageReader(YUV_420_888)` consumer, obtains its `ANativeWindow`, checks the same LG EGL config49/native visual/full attribute set as playback, and attempts to create a real YUV window drawable. It draws A/B/B/A, swaps, acquires each image synchronously with a bounded polling timeout and compares logical Y/U/V planes with validated row/pixel stride and bounds. A/B use identical deterministic RGB expressions including neutral, near-black and saturated 2x2-constant patterns; A stores and reads actual RGBA16F while B applies the existing highp-small-rtz half hypothesis before the same BT.2020 NCL arithmetic. Out-of-range RGB was intentionally excluded from this probe.

The consumer may reject the vendor NV12 native visual, fail acquisition, or return an incompatible format. Any such result is **unsupported-or-error**, not a pass or evidence against fusion. A passing run requires all four images, increasing timestamps, dynamic plane range, matching A/B bytes, matching A/A and B/B bytes, and successful GL/EGL cleanup. Exit2 means unsupported/error, exit3 mismatch, exit0 tested-synthetic raw-YUV equality only. CLI takes one **new** result text path and creates it exclusively. A 30s alarm bounds the isolated workload; host should add its own timeout and check process exit. No device settings or another process's context are touched.

A result file first records `status=running`, then appends final status and counts. Accept only process exit0 plus final completed1/cleanup1/mismatch0/repeat_a0/repeat_b0; running-only is failure. The record is text, not JSON.

There is no performance claim: CPU plane acquisition, readback and 256x256 synthetic input are unsuitable for estimating playback GPU benefit. It does not validate real renderer shader generation, cropping, overlays, metadata, live media, retained frames or the panel. Failure to allocate legal YUV should fall back to bounded before-swap readback on playback's known legal window, or a test-app ImageReader consumer explicitly supported by the device.

Primary specification: [Khronos EXT_YUV_target](https://registry.khronos.org/OpenGL/extensions/EXT/EXT_YUV_target.txt), overview/attachment rules and issue14 require YUV targets; issue16 states that glReadPixels converts to RGBA. Thus using a normal RGBA FBO for layout(yuv), or treating glReadPixels RGB as raw YUV evidence, would be invalid. The ImageReader path is an independent attempt to obtain actual planes through public API24 functionality.
